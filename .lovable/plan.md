# نقل منصة «هنا» إلى مشروع جديد بقاعدة خارجية

## الهدف
إنشاء نسخة جديدة من المشروع تعمل على الخطة المجانية، مرتبطة بمشروع Supabase خارجي تملكه أنت، من دون الاعتماد على Lovable Cloud المتوقف في المشروع الحالي.

## ما تم التحقق منه
- صفحة **App Connections** التي فتحتها خاصة بموصلات الخدمات، وليست مكان ربط قاعدة البيانات.
- هذا المشروع مرتبط بالفعل بـ Lovable Cloud، ولا يدعم فصله أو تحويله مباشرةً إلى قاعدة خارجية.
- الكود يستخدم عميل Supabase المولّد ومتغيرات البيئة، لذلك يمكن نقله من دون إعادة بناء الواجهة.
- المستودع يحتوي على 7 migrations و3 Edge Functions، لكن جدول الريلز والإدارة الثانية لم يُطبقا بعد ضمن migrations الحالية.
- الصور الأساسية موجودة داخل ملفات المشروع، ولا توجد حاليًا Storage buckets يجب نقلها.

## خطوات التنفيذ
1. **إنشاء المشروع البديل**
   - إنشاء مشروع Lovable جديد.
   - اختيار ربط Supabase الخارجي أثناء إعداد المشروع الجديد، قبل تفعيل Lovable Cloud عليه.
   - إبقاء المشروع الحالي كما هو إلى أن تنجح النسخة الجديدة.

2. **نقل التطبيق**
   - نقل كود React، الصفحات، التصميم، الصور، المسارات، ولوحة التحكم إلى المشروع الجديد عبر مستودع Git المتزامن أو نسخة الكود.
   - الحفاظ على نفس تجربة الهاتف والديسكتوب والروابط الداخلية.
   - استخدام عميل Supabase المولّد للمشروع الجديد بدل بيانات اتصال المشروع الحالي.

3. **إعادة بناء قاعدة البيانات الخارجية**
   - تطبيق migrations الحالية بالترتيب نفسه، مع مراجعة `GRANT` وRLS لكل جدول.
   - إضافة migration جديدة لجدول `reels` تشمل بيانات الفيديو والصورة والوصف والعمل المرتبط والترتيب وحالة النشر، مع القراءة العامة والإدارة المحمية.
   - تحديث مشغّل إنشاء المستخدم ليمنح الإدارة لكل من البريد المؤسس الحالي والبريد الإداري الجديد، مع بقاء الأدوار في جدول `user_roles` المستقل.
   - نقل بيانات المحتوى العام المتاحة: العناوين، الحلقات، المؤثرون، الباقات، بوابات الدفع، والريلز التجريبية. سنبدأ بقاعدة مستخدمين ومحادثات جديدة لأن Cloud القديم متوقف.

4. **نقل وظائف الذكاء الصناعي**
   - نشر `parental-assistant` و`influencer-chat` و`analyze-requests` على المشروع الخارجي.
   - استبدال اعتماد الوظائف على بوابة Lovable AI بمزوّد ذكاء صناعي خارجي تختاره لاحقًا، أو تعطيلها مؤقتًا حتى إضافة مفتاح المزود؛ قاعدة البيانات والتصفح سيعملان مستقلين عنها.
   - إضافة التحقق من جلسة المستخدم وصلاحية الإدارة، والتحقق من المدخلات، وإرجاع أخطاء واضحة.

5. **إعداد الدخول والإدارة**
   - إنشاء حساب `osamasafiyi@gmail.com` من شاشة التسجيل في النسخة الجديدة، ثم منحه دور admin تلقائيًا عبر المشغّل.
   - عدم نقل كلمة المرور داخل الكود أو SQL؛ تُستخدم فقط عند إنشاء الحساب عبر نظام المصادقة.
   - اختبار حماية جميع مسارات لوحة التحكم ومنع المستخدم العادي من إدارتها.

6. **التحقق والتحويل**
   - اختبار التسجيل والدخول، كتالوج الأفلام والمسلسلات، صفحات المنتجات، ملفات الأسرة، حفظ محادثات المساعد، إدارة المحتوى، ورفع/نشر الريلز.
   - اختبار سطح المكتب والهاتف، ثم نشر المشروع الجديد.
   - بعد نجاح الاختبارات فقط، تحويل الاستخدام والرابط إلى النسخة الجديدة والاحتفاظ بالمشروع القديم كنسخة مرجعية مؤقتة.

## مسؤوليتك في نقطة الربط
ستحتاج فقط إلى إنشاء **مشروع Lovable جديد** واختيار Supabase الخارجي في بداية إعداده، ثم مشاركة رابط المشروع الجديد معي. لا تستخدم **App Connections** لهذا الغرض، ولا تُدخل مفاتيح خاصة داخل المحادثة أو الكود.

## النتيجة المتوقعة
- ملكية مستقلة للقاعدة الخارجية وحسابات المصادقة.
- استمرار التطبيق ولوحة التحكم والريلز من دون Cloud الحالي.
- قاعدة جديدة نظيفة؛ لا تشمل حسابات أو محادثات Cloud القديم ما لم يصبح التصدير متاحًا لاحقًا.
